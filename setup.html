re-gvs-fvzdx

rg-gvs-fvzdx / Build & setup

Reverse-engineering and browser recompilation of Kidou Senshi Gundam - Renpou vs. Zeon DX (Japan, v2.00). The supplied disc identity is verified in upstream.lock.

Status: 0.1.0 baseline verified on the declared PC Chrome path. Normal boot, menus, selection, active battle, controls, pause/resume, Continue, Game Over and return to the menu passed. This is a bounded first baseline; later checks also passed Side 7 victory into active stage 2 and system/options save persistence across a page reload in the same browser profile. Other modes, campaign completion, browsers and cross-profile saves remain untested.

The baseline uses the original upstream NTSC timing, measured at approximately 60 Hz during active gameplay. Correctness fixes use 0.1.x. Optimization, higher refresh rates and multiplayer are outside this stage.

  • Research wiki URL: deployment pending; see the publishing status below.
  • Research reader source: a Cantonese comparison with GVZG, reusable methods, new findings and further work.
  • Research record: the English technical log, extraction, compilation and test evidence.
  • Upstream improvement candidates: findings to review before any future contribution.
  • 0.1.0 acceptance manifest: exact builds, tests, selected screenshots and limitations.
  • Follow-up checks: the added win and save paths, with test settings and selected evidence.

The structure follows re-gvs-gvzg, with a separate static research reader. The accepted C++ translation is tracked in generated/federation-vs-zeon-dx/; its matched web package is tracked in apps/game/prebuilt/. Private disc inputs, new build workspaces and raw captures stay under ignored .local/. The supplied image is ISO 9660, SLPM-65076, VER = 2.00, NTSC. upstream.lock fixes its full disc and executable hashes.

Publishing status (2026-11-09)

The first Pages workflow attempt stopped before its build steps because GitHub reported an account billing lock. Self-hosted compute has not been shown to resolve that restriction. A separate, owner-only manual diagnostic workflow is prepared to observe one disposable runner assignment; its reviewed runner must reject every workflow step. Offline preparation and independent review do not establish real registration, service compatibility or a deployed wiki. See the research record.

Online Mode (experimental)

An opt-in Online build connects original clients to a private compatible server (gdxsv) through a token-protected gateway. Four browser clients on a PC and a MacBook Pro completed one original 2v2 lobby battle with three consecutive matches and returned to the lobby. The tested server remains private; see docs/online-mode.md and apps/server/README.md.

Local workflow

Run the retained 0.1.0 package without compiling it again:

python3 scripts/game/verify.py
python3 scripts/game/serve.py --build apps/game/prebuilt --disc /private/path/disc.iso

Open http://127.0.0.1:8642/. The matched package includes HTML, JavaScript, WASM, .data and its original build manifest. The .data contains the boot executable, not the complete disc assets; the supported private ISO remains a separate runtime input.

Compile the retained C++

Use Python 3.9+, CMake 3.20+, Ninja, patch, and a Clang C++20 toolchain with std::format. The web build uses Emscripten 6.0.11 and its emdawnwebgpu port. The --disc path compiles tracked C++ directly and extracts the verified boot input into the new workspace. It does not invoke the recompiler or consume historical object files. Use a new --work directory for each build:

python3 scripts/game/build.py --disc /private/path/disc.iso --target web \
  --emsdk /path/to/emsdk --work .local/rebuild-001 --jobs 2

For a native build, use --target native and another work directory.

A fresh PC WSL build from these retained sources produced all four accepted web files byte for byte. See the rebuild record for the exact toolchain, input hashes and comparison scope.

Regenerate a separate translation candidate

Regeneration is distinct from compiling the retained source. These commands write fresh ignored workspaces, preserving the accepted source and prebuilt:

python3 scripts/game/tools.py --jobs 2
python3 scripts/game/regenerate.py --disc /private/path/disc.iso
python3 scripts/game/build.py --translation .local/translation --target native --work .local/native-build --jobs 2
# Activate the existing SDK before the browser build.
python3 scripts/game/build.py --translation .local/translation --target web --emsdk /path/to/emsdk --jobs 2
python3 scripts/game/serve.py --build .local/game-build/web --disc /private/path/disc.iso

The server uses http://127.0.0.1:8642/, HTTP byte ranges and cross-origin isolation. The original ELF is included in the generated .data file; the full disc remains a separate private runtime input. Keep HTML, JS, WASM, data and the build manifest together. Compilation alone does not establish acceptance; the dated 0.1.0 record identifies the tested artifacts. A new build needs its own comparison and runtime checks.

For private archive extraction use 7zz x -o.local/disc ARCHIVE '*.iso'. scripts/game/extract.py --disc DISC --output NEW_DIRECTORY --full-hash verifies the complete image. Normal regeneration checks disc size, actual boot settings and the boot executable hash. Discovery inputs (--entries, --overlays, --vu-records) must come from this game's measured execution.

Keyboard mappings inherited from the runtime are Enter (Start), X (Circle), Z (Cross), A (Square), S (Triangle), arrows (D-pad), and I/J/K/L (left stick). The verified path is Arcade → Federation → Side 7 → Gundam/beam rifle, through a completed loss and return to the menu. At pilot-name entry, Start accepts a default name. Wait for menu transitions before confirming again.

Create a standalone local directory from the tracked matched package, including the server, notices and evidence:

python3 scripts/game/package.py --output .local/package-export-001

The resulting .local/package-export-001 excludes the disc and private saves. It is a local artifact, not a downloadable or published release.

Validation and scope

python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/game/verify.py
node --check tests/pc/run.cjs

The silent PC harness records real Chrome input, screenshots, errors, build identity and audio-ring consumption over an isolated profile. Test execution is through the user's authorized SSH PC, using project-owned resources. Timing tests use --mute-audio, preserving the audio engine; they do not change system volume.

The repository is published at sennett-lau/re-gvs-fvzdx. The research wiki uses GitHub Pages; .github/workflows/wiki-pages.yml deploys only .local/wiki/ when deliberately dispatched on main. No public game server, release or PR is created by that workflow. Third-party notices describe the pinned source and external dependencies.
