rg-gvs-fvzdx / Upstream proposals

This file records findings for later review; it does not authorize a push or pull request. No new EE compiler or runtime correctness defect has been reproduced in the tested boot/menu/Side 7 battle path so far. No reference-game compatibility patch has been applied.

Build input guard: reject transferred metadata as generated C++

  • Source revision: 6526f4803d98e10de50bea3af104a4d26e9df033, CMakeLists.txt generated-source file(GLOB ... "*.cpp").
  • Observed trigger: transferring generated units from macOS using default tar -czf created AppleDouble ._unit_*.cpp and ._table.cpp files in WSL. CMake accepted them in the source glob. Clang then reported binary/null-byte errors while compiling ._table.cpp; the build stopped. The corrected transfer removed only those task-owned sidecars and used COPYFILE_DISABLE=1 tar --no-xattrs. The same real game translation then compiled successfully (200 steps instead of 368).
  • General explanation: a filename suffix is insufficient evidence that a transferred file belongs to a generated source set. This is a packaging/build guard candidate, not an R5900 translation defect.
  • Proposed upstream improvement: emit a generated-file manifest and verify it before CMake configuration, or at minimum reject AppleDouble source filenames with an actionable error. Do not silently accept altered source.
  • Local change: the builder verifies names, lengths and SHA-256 values against translation.json before configuration. The pristine vendor stays unchanged.
  • Portable regression: tests/test_translation.py creates synthetic C++, verifies a matching set, then separately adds an AppleDouble file, alters the source, and removes it. Each mismatch must fail; restoring it must pass.
  • Observed result: the corrected real transfer compiled and reached normal boot and battle on the PC. The synthetic regression passes without game data.

Feature candidate: host handlers for selected guest calls

  • Source revision: 6526f4803d98e10de50bea3af104a4d26e9df033, generated call statements in recomp/codegen.cpp.
  • Observed need: Online Mode replaces 20 original jal statements with host handlers (docs/online-mode.md). Without a compiler option this is done by rewriting a copy of the generated C++ with exact-match checks (scripts/game/online.py). Each call statement already has a stable shape: return address, delay slot, depth-checked unit call, return check.
  • Proposed upstream improvement: accept a list of site=handler pairs and emit handler(c) in place of the unit call at those sites, verifying that the original word is a jal. Guest code and memory stay unchanged, and diagnostics can name the hooked sites.
  • Regression test: tests/test_online.py checks exact single replacement, duplicate and wrong-callee rejection on synthetic C++.
  • Observed result: the hooked build reached the original lobby and a four-client battle; the default build is unchanged. This is a feature candidate, not a defect.

See research.md for the complete experiment and remaining acceptance limits. No upstream contact or submission has occurred.
